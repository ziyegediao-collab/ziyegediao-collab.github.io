1. 变更控制流程（逢变必走）

提出任何人提出变更请求
→
评估对范围、进度、成本的影响
→
审批变更控制委员会拍板
→
更新获批后更新基准和文档
→
执行通知团队按新基准干活

❌ 不能先斩后奏、事后补记录；被否决也要记录原因并告知提出人。评估是流程里面的一步：先提交正式请求、进入流程，再在流程里评估。完整版（含六步、CCB 和一道例题）见 变更控制 · 一张图看懂 →

2. 项目五大过程组

启动定章程、识别干系人
→
规划定范围、排进度、算预算

3. 挣值判断（一句话记牢）

PV 计划价值到今天原计划该干的活
＋
EV 挣值实际干完的活
＋
AC 实际成本已经花的钱
＋
BAC 完工预算整个项目一共要花多少钱

CPI = EV ÷ AC：小于 1 超支，大于 1 节约。SPI = EV ÷ PV：小于 1 落后，大于 1 提前。分子永远是 EV。完整版（含 EAC / ETC / VAC 和一道例题）见 挣值管理 · 一张图看懂 →

4. Sprint 循环

规划会定目标、拉取工作
→
每日站会进展、计划、阻碍
→
开发工作做出可用的增量
→
评审会给干系人演示、拿反馈
→
回顾会复盘流程、定改进行动
↻
下一个 Sprint

Sprint 长度固定，中途不延长；新需求要进 Sprint 得先评估对目标的影响、等量置换。完整版（含 DoD、插单规则和第 4 个 Sprint 那道例题）见 Sprint 循环 · 一张图看懂 →

5. 风险管理流程

识别找出风险
→
登记立刻记入风险登记册
→
分析概率 × 影响排优先级
→
应对规避 / 转移 / 减轻 / 接受
→
执行触发条件到了就动手
→
监控盯效果、盯次生风险

高概率高影响要主动应对；应对失效了就重新评估、更新登记册、制定新策略。完整版（含四种应对、触发条件和一道例题）见 风险管理 · 一张图看懂 →

6. 冲突与干系人问题处理顺序

了解私下了解诉求和原因
→
协商围绕共同目标引导协商
→
调整改沟通方式或参与计划
→
跟进确认问题真的解决

升级、投票、调离、施压都是最后手段，考试里一上来就选这些基本都是错的。完整版（含五种处理方式和一道例题）见 冲突与干系人问题 · 一张图看懂 →

7. 预期货币价值 EMV（一张算账卡）

列方案不做 / 方案 A / 方案 B / 两个都上
→
算总成本花的钱 + 剩下概率 × 出事损失
→
比大小四个都算完，选最低的

“最保险”不是算法，概率压得最低的方案往往花钱最多；“两个都上”几乎总是全场最贵。完整版（含四步算账法和两道错题的完整算账）见 预期货币价值 · 一张算账卡 →
